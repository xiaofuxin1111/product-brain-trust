## 四、七个模块的必答项（对话最小集）

每模块只在对话里问 2-4 个必答项；其余条目是"条件触发"——用户说到相关内容时才启用。这样 44 条题库不会变成 44 个问题。

| 模块 | 必答项（对话里一定会问） | 条件触发项 |
|---|---|---|
| M1 谁的什么问题 | M1-1 说清问题、M1-2 为谁、M1-5 真正想达成什么 | M1-3 特别想要的人、M1-4 是问题还是解法、M1-6 为什么是现在、M1-7 需求冲突、M1-8 一句话讲清差别（多由开场自述直接判定） |
| M2 凭什么觉得有人要 | M2-1 证据来源、M2-3 现在怎么凑合、M2-5 代价多大 | M2-2 客套话、M2-4 空头支票、M2-6 找过方案吗、M2-7 有没有带节奏、M2-8 有没有照着做、M2-9 聊之前定了要搞清什么 |
| M3 值不值得换 | M3-1 账算不算得过来、M3-2 要付出什么 | M3-3 总代价值不值、M3-4 几种解法、M3-5 目标优先级 |
| M4 谁会回来 | M4-1 使用频率、M4-3 什么时候想起你 | M4-2 攒下什么、M4-4 几步拿到好处、M4-5 第一次够不够意外、M4-6 变好还是变糟 |
| M5 第一版做多大 | M5-2 做几件不做什么、M5-1 两个目标 | M5-3 需求可验证、M5-4 怎么算成功、M5-5 内容谁维护、M5-6 五层结构、M5-7 第一次打开会不会懵 |
| M6 怎么活下去 | M6-1 谁付钱、M6-2 成本结构 | M6-3 用户怎么知道你、M6-4 凭什么是你、M6-5 多边利益 |
| M7 哪一步最可能死 | M7-1 最怕的问题、M7-2 风险在哪侧、M7-4 做不做得出来 | M7-3 时间点（原 M1-6 的风险版） |

必答项合计 17 条（M1 三条 / M2 三条 / M3 两条 / M4 两条 / M5 两条 / M6 两条 / M7 三条），其中约 6 条靠"听"完成、不占提问额度；实际提问约 20-23 个。

## 五、模块顺序与通过标准

| 顺序 | 模块 | 过了就转下一模块的标准 |
|---|---|---|
| 1 | M1 谁的什么问题 | 能说出具体的一个人群 + 一个具体场景 + 一句不带功能词的问题描述 |
| 2 | M2 凭什么觉得有人要 | 说清现有证据属于哪一类（事实/客套/空头）；"现在怎么凑合"有答案 |
| 3 | M3 值不值得换 | 用户能说出换过来的三个代价，并承认账算不算得过来 |
| 4 | M4 谁会回来 | 说出使用频率 + 一个会想起产品的场景 |
| 5 | M5 第一版做多大 | 说出第一版只做的 3-5 件 + 明确不做的一栏 |
| 6 | M6 怎么活下去 | 说出谁付钱、单用户成本，二者至少有个粗数 |
| 7 | M7 哪一步最可能死 | 说出一个最怕的失败原因 + 最难做的一块打算怎么过，并承认这两样都还没验过 |

"不知道"也算过关，记为缺口写进报告——不纠缠、不停留。

### 8.3 方法教训（写进蒸馏规范）

1. **清单/总结类章节必须精读**。按"判断密度"选章会系统性跳过全书最后一章，而最后一章往往正是作者亲手做的提炼。
2. **案例不得推测**。原文只有一句话列举时，宁可不设案例，也不用推测填充——已按此原则处理 J11、J13。
