# 产品专家智囊团（Product Brain Trust）

> 帮零产品经验、零编程经验的普通人，在动手用 AI 编程做产品之前，先把想法聊清楚。

**当前版本：v1.0.0**（2026-11-06）

## 为什么做这个

很多人想趁 AI 编程的热潮做点东西——小工具、小程序、网站、个人作品集。但大部分人是产品小白：不是想法不够多，而是想法里全是没验证过的假设。做出来才发现没人要，白费几周。

这个项目把六本产品经典书的知识，蒸馏成一套**问答式诊断流程**：用户带着想法进来，AI 扮演一位几十年经验的产品专家，通过聊天把想法过一遍检查，最后给出一张产品体检单——哪里有疏漏、每个疏漏怎么解决，一条条写清楚。

## 它怎么工作

对话分七块走完一个想法的完整链路：

| # | 检查什么 |
|---|---|
| 1 | 解决谁的麻烦，具体什么麻烦 |
| 2 | 你为什么觉得有人要 |
| 3 | 他愿不愿意换 |
| 4 | 他会不会再来 |
| 5 | 第一版的功能能砍到多小 |
| 6 | 这事怎么养活自己（自己用、不图钱的产品走 B 路，不问付钱） |
| 7 | 这款产品最有可能死在哪 |

聊完产出**产品体检单**（最多三个"必须先补"的缺口 + 每个缺口的具体解决方法）；用户要时再生成一页纸**《产品需求文档》**，可直接复制给 AI 编程工具开工。

## 知识底座

六本产品经典书 → 蒸馏出 **44 条判定项**（每条七字段：判定什么 / 过关信号 / 不过关信号 / 小白版问法 / 答不上来怎么引导 / 常见误判 / 怎么解决）：

《The Mom Test》《上瘾》《俞军产品方法论》《人人都是产品经理》《启示录》《用户体验要素》

**知识层对用户完全不可见**——用户只经历说人话的对话，永远不需要知道背后是哪本书。

## 安装

把 `产品专家智囊团/` 文件夹改名为 `product-brain-trust/`，放进 `~/.workbuddy/skills/`（Windows 路径：`C:\Users\<你的用户名>\.workbuddy\skills\`），重启 WorkBuddy 生效。

装好后新开一个对话，说"我想做个 AI 工具帮小商家写朋友圈文案"这类话，它会自动接手。

## 设计原则（改版时不能破的规矩）

1. **说人话**：不举例子、不打比方、不提书名、不造词；术语出口当句必须跟白话解释
2. **诊断点名具体**：不说"这块是空的"，直接说哪件事缺什么信息
3. **只评判想法，不评判人**
4. **发现即给**：缺口连同解决方法当场给，给完立刻推进，对话不中断
5. **不替用户拍板**：给证据和风险排序，判断权归用户
6. **不做市场调研、不编数据**：只告诉用户该去哪找什么信息

完整规则见 `产品专家智囊团/对话脚本.md`（七条硬规则 + 运行自检）和 `产品专家智囊团-需求共识.md`。
